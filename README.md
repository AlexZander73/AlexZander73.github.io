## Portfolio project catalog

**Edit `data/showcase.json` once.** Home, Play, Campaign, About, Products and the
Support directory all load it through `assets/js/project-catalog.js`. There is no
hardcoded fallback product list. If the JSON cannot load, the directory displays
an explicit error instead of silently showing stale entries.

- `title`, `type`, `blurb`, `image`, `url`, `platforms` and `tech` supply shared
  listing content. Local paths resolve from the site root, including subpath hosting.
- `featured: true` identifies featured products. `campaignOrder` sets their shared
  display order; 0 is first, and orders 0–5 occupy Campaign’s large highlight cards.
- `status: "shipped"` counts toward launches and unlocked stages. Other statuses
  remain in development. `previewAvailable: true` explicitly enables entry to an
  in-development product page without increasing launch/completion counts.
- `category` drives the experiment/infrastructure filters independently of status.
- Add a `product` object to include a local product page in Products. Its `supportUrl`
  automatically adds it to Support; `privacyUrl` records its privacy page. The local
  product directory must match the record’s `id`.

For example, ProjectVault’s single entry controls every listing and places its
preview first. Its product website lives at `products/projectvault/`, with support
and privacy pages alongside it. It remains in development until a public release.

### Generated files and checks

After adding or editing a project, run:

```sh
python3 scripts/build-catalog.py
python3 scripts/build-catalog.py --check
node --test scripts/project-catalog.test.cjs
```

The generator validates unique IDs, local assets, product pages and help links.
It writes `products/catalog.json` for compatibility and discovers public HTML
pages for `sitemap.xml`. **Do not hand-edit either generated file.** The Products
Catalog GitHub workflow uses the same script when catalog or page source changes.
Existing product `content.json` and `product:*` HTML metadata are page-specific
material; they no longer feed portfolio listings. The unused legacy
`data/projects*.json` files and GitHub repository sync are not listing sources.

### About tools and launch count

About’s Product Launches trophy and Campaign’s Stages Unlocked count only records
with `status: "shipped"`. Tools of the Trade combines `platforms` and `tech` across
all records, including work in progress, removes duplicates without regard to
capitalization, and sorts alphabetically. Use only confirmed platforms and tools.

About-only additions and exclusions live in `data/about.json`, under `tools.add`
and `tools.hide`. Exclusions win over additions and affect About only.

Empty grid positions are generated by the layout. Do not invent catalog entries
to fill them; they do not contribute to project or completion counts.

## Dragon Treasury

The interactive 3D treasury lives at [`/projects/DragonTreasury/`](https://zachmackay.com/projects/DragonTreasury/). Its editable source is in `tools/dragon-treasury/`; generated public files are in `projects/DragonTreasury/`. It uses the existing `ProjectCatalog` loader and `data/showcase.json` directly, so catalog updates appear without rebuilding.

To change the world, run `npm ci`, `npm test`, and `npm run build:site` from `tools/dragon-treasury/`. Commit source and generated output together; the Treasury workflow checks they agree. MainWebsite's normal deployment publishes the route. See the source README for local preview and accessibility controls.
